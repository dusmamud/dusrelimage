## The shared contract in this directory

[`test-vectors.json`](test-vectors.json) is the contract every language
must pass: one entry per case, with a fixture name (generated by
`dusrelimage mock`, deterministic seed), the op, its options, and the
expected output (dimensions and/or pixel spot-checks and/or error code).
Rust, Python and JS all run these vectors and must agree.

## Honest limits of v0.1.0 (from SPEC section 3 and the core workers)

- AVIF input does NOT decode (`UNSUPPORTED_FORMAT`); AVIF output works,
  lossy 8-bit only.
- WebP output is always lossless; `quality` / `effort` are ignored for
  WebP.
- `keep_exif` / `dpi` / `progressive` are accepted but not honoured
  (the `image` 0.25 encoders expose no such switches).
- `compress_to_size` quality search is JPEG / AVIF only.
- TIFF input decodes but has no `ImageFormat` variant and falls back to
  PNG output.
- `bulk_process` signature is `bulk_process(inputs, &BulkOp)` (op +
  options merged into one enum), and `BulkOp::Collage` returns
  `INVALID_ARGUMENT` per item (collage must be called via `make_collage`).
- Collage output is always PNG. Pixelate rect out-of-bounds ->
  `INVALID_ARGUMENT`. Palette returns up to `count` entries.
- GIF encode is first-frame only for animated input. No HEIC.
  Whole image in memory, no streaming.

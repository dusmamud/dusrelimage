# dusrelimage website

Public website for **dusrelimage** — the offline image toolkit (compress,
resize, crop, convert, watermark, annotate, colour picker, palette, collage,
pixelate). Built with [Astro](https://astro.build) +
[Starlight](https://starlight.astro.build). Fully static: no SSR, no backend,
no database.

Deployed to Cloudflare Pages at
<https://dusrelimage.pages.dev> (see `website.yml` in the repo root).

## Run it

```bash
npm install
npm run dev      # local dev server at http://localhost:4321
npm run build    # production build into ./dist/ (builds the WASM playground first)
npm run preview  # preview the production build locally
```

Requires Node 18+ and `wasm-pack` (for the playground WASM build — see below).

## What's here

| Path | What it is |
| --- | --- |
| `src/pages/index.astro` | Landing page — hero, install commands, 10-tool grid, honest limits |
| `src/pages/playground.astro` | In-browser playground — pick a local image, run compress / resize / crop / convert / watermark / pixelate / palette / colour picker, download the result. Files never leave the browser. |
| `src/content/docs/` | Starlight docs: quickstart, options, error codes, one page per tool (10), info & bulk, comparison, changelog |
| `src/lib/wasm-pkg/` | WASM build output (gitignored, regenerated by `npm run build`) |
| `public/wasm/` | Copy of the WASM build served to the playground (gitignored) |
| `public/favicon.svg`, `public/og.svg` | Favicon + social card |

## How the playground's WASM works

`npm run build` runs `prebuild` first (`scripts/build-wasm.mjs`), which runs
`wasm-pack build --target web crates/dusrelimage-wasm` into
`src/lib/wasm-pkg/` and copies it to `public/wasm/`. The playground
lazy-loads `/wasm/dusrelimage_wasm.js` on first use.

The build script **fails loudly** if `wasm-pack` is missing or the build
fails — the site must never ship a playground that silently does nothing.

## Docs

Docs are in English for v0.1; the error messages in the package itself are
bilingual (every error carries `message_en` and `message_hi`). Every doc page
carries the honest-limits note: v0.1.0 has no HEIC support, AVIF encode is
lossy-only / 8-bit, GIF encode is first-frame only for animated input, and
the whole image lives in memory with no streaming mode.
